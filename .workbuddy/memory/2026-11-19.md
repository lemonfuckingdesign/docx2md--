## docx2md 项目 GitHub 成品化重构（已完成）

将原单文件 2141 行的 `docx2md.py` 重构为模块化工程，目标仓库 https://github.com/lemonfuckingdesign/docx2md。

**关键背景/问题**：原始项目只有 4 个文件，主程序叫 `docx2md.py`，但 docstring 和 3 个配套文件全引用不存在的 `docx2dify.py`，一键脚本全部失效。

**用户决策**：允许全面重构主程序；只补基础四件套（不做 tests/examples/pyproject/CI）；MIT 许可证 © 2026 lemonfuckingdesign；README 用真实仓库地址。

**最终结构**：入口 `docx2md.py`（薄）+ `cli.py`（argparse/logging/编排）+ `config.py`（常量/正则/FLAT_MODE 访问器）+ `core/` 五模块（recognize/text/split/render/convert）。依赖单向：config→recognize→text→split→render→convert→cli。

**保真策略（核心经验）**：
- 用 AST 按行号逐字提取函数/常量，函数体零改动；自动 symtable 分析生成 import。
- FLAT_MODE 改为 config 的访问器 `set_flat_mode/is_flat_mode`，避免 from-import 值拷贝；render 两处读取替换为 `is_flat_mode()`，cli 写入用 `set_flat_mode(True)`。
- 拆分脚本必须始终读仓库外的原始备份作为源——读已被覆盖的薄入口会导致常量提取为空（踩过坑）。
- symtable 不识别类型注解里的名字（如 `path: Path`），需显式从 AST annotation 补依赖。
- 验证：用 python-docx 生成 7 个覆盖四类体例+多篇+边界的样例，重构前后 md/csv 的 SHA-256 全部一致（含 flat 模式）。CSV 的「输出文件」列含绝对路径，不同输出目录会有差异，比对时要剔除该列。
- 表格顺序 bug 本次明确不修（会改变输出破坏基线），列入 README 已知限制。

**配套文件**：bat/sh 文件名统一为 docx2md.py、依赖改用 requirements.txt；使用说明.md 补 CLI 选项；新增 README.md/requirements.txt(python-docx>=1.1.0)/LICENSE/.gitignore。全局无 docx2dify/report.csv 残留。

**状态**：全部完成并通过验证。原文件备份在 `C:\Users\yundesign\AppData\Local\Temp\docx2md-refactor\backup\`。未执行 git init/推送（留给用户决定）。
